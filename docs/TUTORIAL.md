# vitul 脚本教程（只讲脚本，不碰宿主）

> **这份教程假设你只会脚本。** 不需要会 Rust，不需要知道引擎怎么实现。
> 你的脚本运行在某个宿主程序里——宿主给你提供了哪些函数（比如 `log`、`tap`、`battery_level`），由宿主的文档决定；本教程只教**语言本身**，以及每个脚本都自带的 13 个内置函数。
> 教程里的脚本行为全部被 `tests/` 里的测试真实执行验证过。
>
> 写宿主集成代码（Rust 侧）？那不是这份文档的事，看 `docs/HOST_GUIDE.md`。

## 1. 第一个脚本

脚本是一个 `.vt` 文件，内容由**函数定义**组成——所有函数**平铺在顶层**、彼此独立，不存在谁包在谁里面：

```text
┌── hello.vt ─────────────────────────────┐
│                                         │
│  func helper(x) {          ← 函数 1（顶层，独立）      │
│      x * 2                                              │
│  }                                                      │
│                                                         │
│  func main() {             ← 入口（宿主只调这一个）     │
│      let a = helper(21)    ←   执行到这里才【调用】helper │
│  }                                                      │
│                                                         │
└─────────────────────────────────────────┘
```

**执行模型**：平时整份脚本只是"躺着的定义"，什么都不执行。宿主调用 `main` → main 的函数体逐句执行 → 碰到 `helper(21)` 就跳去执行 helper、拿到返回值 → 回到 main 继续。没被调用的函数全程不跑。

**入口叫什么由宿主决定**——`main` 只是本教程所有示例跟随的习惯，不是语言强制。宿主可以调任何函数（`engine.call(&script, "导出报表", ...)` 也是合法入口），所以**多入口脚本**很常见：一份脚本定义一堆任务函数，宿主按任务名挑着调。写脚本前先跟你的宿主确认「它调哪个名字」。

**两条结构规则**：
1. **顶层只能放函数定义**——不能像 Python 那样在顶层直接写语句，想执行什么包进函数让宿主调
2. **函数不能嵌套定义**——`func` 只能写在最外层，函数体内再写 `func` 是编译错误

一个稍微像样的例子（本教程的例子都会像这样带注释）：

```text
// grade.vt —— 按分数给等级
func level(score) {
    if score >= 90 {
        "优秀"
    } else if score >= 60 {
        "及格"
    } else {
        "不及格"
    }
}

func main() {
    let s = 87
    log("分数 " + to_str(s) + " → " + level(s))
}
```

怎么运行取决于宿主：有的宿主提供命令行（`宿主名 grade`），有的在 App 里点按钮，有的定时触发。**写好文件、交给宿主，就这些。**

## 2. 语言基础

### 2.1 语句与换行

- **没有分号**。一行一条语句，换行即结束。
- 写了 `;` 会报错：`unexpected character ';'`——删掉就行。
- 一条语句太长想换行？**在运算符后面换**（`+`、`&&` 等放在行尾）：

```text
log("第一段" +
    "第二段")
```

### 2.2 变量

```text
let x = 10           // 创建变量
x = x + 5            // 重新赋值（= 是赋值，== 才是比较）
let y = x * 2        // y = 30
```

- 变量**不用声明类型**，由右边的内容决定
- **一个变量的类型终生不变**：`x = 1` 之后 `x = "文本"` 会编译报错
- 重复 `let` 同名变量会在内层遮蔽外层（一般用不到，知道即可）

### 2.3 数据类型：一共 6 种

| 类型 | 字面量例子 | 说明 |
|---|---|---|
| `i64` | `0`、`42`、`-7`、`1234567890123` | 整数（64 位有符号，约 ±922 亿亿。42 只是举例，**不是上限**） |
| `f64` | `3.14`、`0.5`、`2e3` | 浮点数（**必须以数字开头**：`0.5` 对、`.5` 错——点号开头是元组索引语法；带小数点或科学计数法才是浮点） |
| `bool` | `true`、`false` | 布尔 |
| `str` | `"文本"`、`"中文\n换行"` | 字符串（UTF-8，长度按字符算） |
| 元组 | `(1, "a", true)` | 打包多个值，见 [5. 元组详解](#5-元组详解) |
| `()` | `()` | unit，表示"没有值" |

**整数边界**（两条，都明确报错不悄悄算错）：
- 字面量写超范围 → `integer literal overflows i64`
- 运算结果超范围 → `i64 add overflow`（减乘除同理），**不会回绕成负数**

**字符串转义**：`\n` 换行、`\t` 制表、`\r` 回车、`\\` 反斜杠、`\"` 引号。

### 2.4 运算符

**算术**（`*` `/` `%` 优先于 `+` `-`）：

```text
7 + 2       // 9
7 - 2       // 5
7 * 2       // 14
7 / 2       // 3        整数除法向零截断
7 % 2       // 1        取余
7.0 / 2.0   // 3.5      浮点除法
-7 % 2      // -1       余数符号跟被除数
```

**比较**（产出 bool）：

```text
1 == 1      // true     等于
1 != 2      // true     不等于
1 < 2       // true
2 <= 2      // true
3 > 2       // true
3 >= 4      // false
"a" < "b"   // true     字符串也能按字典序比
```

**逻辑**（两边必须是 bool）：

```text
!true               // false
true && false       // false    并且（右边可能被跳过——短路）
true || false       // true     或者
```

**优先级从高到低**：`!` 和一元 `-` → `* / %` → `+ -` → `< <= > >=` → `== !=` → `&&` → `||`。拿不准就加括号。

**类型规则（重要）**：
- 整数和浮点**不能混算**：`1 + 2.5` 编译错误。先转换：`to_f64(1) + 2.5`
- 字符串只支持 `+` 拼接：`"a" + "b"` ✓，`"a" - "b"` ✗
- 除零报错（`1 / 0` → `division by zero`），不会得到无穷大

### 2.5 类型转换

```text
to_i64(2.9)      // 2        浮点 → 整数（向零截断）
to_f64(3)        // 3.0
to_str(42)       // "42"
to_str(3.5)      // "3.5"
to_str(true)     // "true"
```

只有这三个转换函数。整数 ↔ 浮点不能隐式转换，字符串和数字不能隐式互转。

### 2.6 注释

```text
// 行注释
/* 块注释，
   跨行也没问题（不嵌套，第一个 */ 就结束） */
```

## 3. 控制流

### 3.1 if / else if / else

```text
func classify(n) {
    if n < 0 {
        "负数"
    } else if n == 0 {
        "零"
    } else {
        "正数"
    }
}
```

条件必须是 bool——`if 1 { ... }` 编译错误（没有"非零即真"那种隐式转换）。

### 3.2 if 当表达式用（把 if 的值赋给变量）

```text
func max_of(a, b) {
    let bigger = if a > b { a } else { b }
    bigger
}
```

⚠️ 当表达式用的时候 **else 必须写**（两个分支都要能给出值）。`let x = if c { 1 }` 是编译错误。

### 3.3 while

```text
func countdown(from) {
    let n = from
    while n > 0 {
        log(to_str(n))
        n = n - 1
    }
    n
}
```

### 3.4 for：遍历一个整数区间

```text
func sum_to(n) {
    let t = 0
    for i in 0..n {        // i 依次取 0, 1, 2, ..., n-1
        t = t + i
    }
    t
}
```

⚠️ **`0..n` 是左闭右开**：`0..10` 是 0 到 9，共 10 个数。`sum_to(100)` = 4950，不是 5050。循环变量 `i` 只在循环体内可用。

### 3.5 break 与 continue

```text
func first_square_over(n) {
    let i = 0
    while true {              // "死循环" + break 是常见写法
        if i * i > n {
            break             // 跳出整个循环
        }
        i = i + 1
    }
    i                         // first_square_over(30) = 6
}

func count_odd_under(n) {
    let c = 0
    for i in 0..n {
        if i % 2 == 0 {
            continue          // 跳过本轮，直接进入下一轮
        }
        c = c + 1
    }
    c                         // count_odd_under(10) = 5
}
```

`break` / `continue` 只能在循环体里用，写在外面是编译错误。

### 3.6 嵌套深度上限 64

括号、花括号、运算符链、else-if 累计嵌套不能超过 64 层。超了报 `nesting too deep`。这是保护：更深会让引擎自己崩溃，提前报错是特性。人写的代码到不了 64；机器生成的超长表达式拆成多个 `let`。

## 4. 函数

### 4.1 定义与调用

```text
func greet(name: str) {
    log("你好，" + name)
}

func main() {
    greet("小明")          // 调用自己定义的函数
}
```

### 4.2 参数：不写类型，除非需要

参数类型由编译器自动推断。大多数时候不写：

```text
func double(x) { x * 2 }              // x 是 i64（从 x * 2 推断）
func shout(s) { s + "!" }             // s 是 str（从字符串拼接推断）
```

推断不出来时会**默认按 i64**。两种情况需要写标注：

```text
func echo(s: str) { s }               // 参数没被用到/只透传 → 不标注收字符串会报错
func scale(x: f64) { x * 0.5 }        // 明确要浮点参数
```

**记忆方法**：报错信息会明说 `argument type mismatch: expected i64, got str. Annotate the parameter (e.g. \`x: str\`)` —— 照着加标注就行。

### 4.3 返回值

```text
func add(a, b) {
    a + b                 // 末位表达式就是返回值（不需要 return）
}

func div_safe(a, b) -> f64 {     // -> f64 是返回类型标注（可选，写了当校验）
    if b == 0.0 {
        return 0.0               // return 提前退出
    }
    a / b
}

func noop() {
    // 什么也不返回：返回 ()
}
```

### 4.4 多返回值（元组）

```text
func divmod(a, b) {
    (a / b, a % b)
}

func use() {
    let r = divmod(17, 5)
    log(to_str(r.0) + " 余 " + to_str(r.1))     // 3 余 2
}
```

详见 [5. 元组详解](#5-元组详解)。

### 4.5 递归

```text
func fib(n) {
    if n < 2 {
        n
    } else {
        fib(n - 1) + fib(n - 2)
    }
}
```

递归深度有上限（默认 256 层），没写出口条件的递归会报 `call depth limit exceeded`，不会栈溢出。

### 4.6 调用宿主提供的函数

除了下面的 13 个内置函数，宿主还可能提供自己的函数（`log`、`tap`、`battery_level`……）。它们对脚本来说就是**普通函数**——你不知道内部实现，只知道名字和参数（宿主的函数文档会写）。

```text
func main() {
    let lv = battery_level()        // 宿主函数：查电量（示例）
    if lv < 20 {
        log("电量告急")
    }
}
```

两种失败通道（如果宿主的函数会失败）：函数直接让本次脚本终止（宿主会收到错误）；或者宿主选择返回 `(是否成功, 结果)` 元组让你自己判断。**遇到 `(bool, ...)` 形状的返回值，先判第一个。**

## 5. 元组详解

元组把**几个值打包成一个值**——「几个」编译期就固定，每个位置类型可以不同。

### 5.1 创建与取值

```text
let point = (100, 200)              // (i64, i64)
let person = ("小明", 25, true)     // (str, i64, bool) —— 混合类型合法
let nested = ((1, 2), (3, 4))       // 元组里套元组
let single = (1,)                   // 单元素必须带尾逗号！(1) 没逗号只是括号分组
let e = ()                          // 这是 unit，不是"空元组"
```

**取值用 `.编号`**——编号是字面量（从 0 开始），取第几个在编译期就确定，运行时零开销：

```text
person.0        // "小明"
person.1        // 25
person.2        // true
person.3        // ✗ 编译错误：tuple index 3 out of range (len 3)
t.i             // ✗ 编译错误：expected tuple index（编号不能是变量）
nested.1.0      // 3       嵌套取值连点即可
```

### 5.2 最重要的用途：多返回值 + 标志位

```text
func divmod(a, b) {
    (a / b, a % b)
}

// 没有"可能失败的返回值"这种概念，官方姿势是 (是否成功, 结果) 标志位：
func safe_div(a: f64, b: f64) {
    if b == 0.0 {
        (false, 0.0)
    } else {
        (true, a / b)
    }
}

func use2() {
    let ok = safe_div(10.0, 2.0)
    if ok.0 { ok.1 } else { 0.0 }
}
```

### 5.3 四条规矩

1. **没有解构**——`let (a, b) = t` 不支持，用 `.0`/`.1` 逐个取
2. **没有相等比较**——`t1 == t2` 编译报错；逐字段比：`t1.0 == t2.0 && t1.1 == t2.1`
3. **参数不用标注也能收元组**——`func first2(t) { t.0 + t.1 }` 直接可用；宿主传**更长**的元组也行（多出的元素无害），不够时运行时报错
4. **最多 8 个元素**——第 9 个报 `the maximum is 8`。真需要更多：嵌套元组 `((1,2,3,4),(5,6,7,8,9))`，或拆成多个变量

## 6. 字符串

字符串**只有 `+` 拼接**，没有方法调用。所有操作走内置函数 + 宿主函数：

```text
len("中文")               // 2         按字符数（不是字节数！）
contains(pw, "123")       // bool      包含子串吗
substr("中文abc", 0, 2)   // "中文"    按字符截取（起点, 长度）
to_str(42)                // "42"
```

常用模式：

```text
// 拼报告行
log("电量 " + to_str(lv) + "%（" + tag + "）")

// 判断前缀/后缀？内置没有——找宿主要函数，或用 substr 自查
substr(filename, 0, 5) == "probe"     // "以 probe 开头"的土办法
```

⚠️ 从 rhai 迁移的注意：rhai 的 `trim()`/`replace()` 是**原地修改**（`out.replace("\\","_")`），vitul 没有这种语义——找宿主要对应的纯函数。

## 7. 内置函数完整参考

每个脚本自带 13 个内置函数（**名字是保留字**，不能定义同名函数）：

| 函数 | 参数 → 返回 | 说明 | 例子 |
|---|---|---|---|
| `abs(x)` | i64 → i64；f64 → f64 | 绝对值（类型跟随实参） | `abs(-3)` → 3 |
| `min(a, b)` | 同上 | 较小值 | `min(1, 2)` → 1 |
| `max(a, b)` | 同上 | 较大值 | `max(1, 2)` → 2 |
| `sqrt(x)` | f64 → f64 | 平方根 | `sqrt(9.0)` → 3.0 |
| `floor(x)` | f64 → f64 | 向下取整 | `floor(2.7)` → 2.0 |
| `ceil(x)` | f64 → f64 | 向上取整 | `ceil(2.1)` → 3.0 |
| `pow(a, b)` | f64, f64 → f64 | 幂 | `pow(2.0, 10.0)` → 1024.0 |
| `len(s)` | str → i64 | 字符数（非字节） | `len("中文")` → 2 |
| `contains(s, sub)` | str, str → bool | 包含子串 | `contains("abc", "b")` → true |
| `substr(s, start, len)` | str, i64, i64 → str | 按字符截取 | `substr("中文abc", 0, 2)` → "中文" |
| `to_i64(x)` | f64 → i64 | 截断转换 | `to_i64(2.9)` → 2 |
| `to_f64(x)` | i64 → f64 | 提升 | `to_f64(3)` → 3.0 |
| `to_str(x)` | i64/f64/bool/str → str | 转字符串 | `to_str(42)` → "42" |

**泛型规则**：`abs`/`min`/`max` 一次调用里全是整数 → 结果整数；全是浮点 → 浮点；**混用（`min(1, 2.5)`）编译报错**。

**隐藏规则**：`to_str(未确定类型的变量)` 会把变量按 i64 处理——想格式化浮点数，给参数加 `: f64` 标注。

## 8. 报错怎么看

错误格式：**`[阶段] error at 行:列: 消息`**。行:列 指向你文件里的位置（列按显示宽度算，中文算 2 格，caret 落在你肉眼看到的地方）。

| 错误信息 | 原因 | 修法 |
|---|---|---|
| `expected Func, found ...` | 顶层写了语句 | 包进函数（入口名由宿主约定，习惯叫 `main`，见 §1） |
| `unexpected character ';'` | 写了分号 | 删掉（本语言无分号） |
| `type mismatch: expected i64, found str` | 类型不匹配 | `to_str()`/`to_i64()` 转换，或统一类型 |
| `argument type mismatch: expected i64, got str. Annotate the parameter...` | 参数类型推断成了 i64 | 给参数加标注：`(x: str)` |
| `tuple index 2 out of range (len 2)` | 元组索引越界 | 检查 `.N` 和元组实际长度 |
| `undefined function \`foo\`` | 函数名打错 / 宿主没提供 | 核对宿主文档 |
| `function \`len\` is a reserved built-in name` | 函数名撞内置 | 换名 |
| `nesting too deep (limit 64)` | 嵌套太深 | 拆成多条 `let` |
| `the maximum is 8` | 元组/调用实参超 8 | 拆分或嵌套元组 |
| `step (gas) limit exceeded` | 死循环或计算量超预算 | 检查循环出口（宿主函数如 `sleep` 不消耗步数） |
| `call depth limit exceeded` | 递归没出口 | 检查终止条件 |
| `memory limit exceeded ...` | 字符串拼接超大 | 换算法 |
| `division by zero` | 除零 | 先判零 |

## 9. 完整示例：巡检任务脚本

把前面的知识串起来。这个脚本假设宿主提供了 4 个函数：`log(msg)`、`battery_level()`、`find_text(text)`（返回 `(是否找到, x, y)`）、`tap(x, y)`：

```text
// patrol.vt —— 电量巡检：低电量自动进省电模式
// 宿主函数：log(msg)、battery_level()、find_text(t) -> (found, x, y)、tap(x, y)

func level_tag(lv) {
    if lv >= 80 {
        "良好"
    } else if lv >= 30 {
        "可用"
    } else {
        "告急"
    }
}

// 连续按"减"把亮度降到目标以下，返回按键次数
func step_down_to(lv, target) {
    let pressed = 0
    while lv > target && pressed < 20 {      // pressed 上限防死循环
        lv = lv - 5
        pressed = pressed + 1
    }
    pressed
}

func main() {
    let lv = battery_level()
    log("当前电量 " + to_str(lv) + "%（" + level_tag(lv) + "）")

    if lv < 30 {
        log("进入省电流程")
        let n = step_down_to(lv, 10)

        let btn = find_text("省电模式")
        if btn.0 {
            tap(btn.1, btn.2)
            log("已点击省电模式")
        } else {
            log("找不到省电按钮，需人工处理")
        }

        log("共按下 " + to_str(n) + " 次减键")
    } else {
        log("电量充足，无需处理")
    }
}
```

逐段讲解：
- `level_tag`：if 语句链 + 末位表达式返回字符串
- `step_down_to`：while + 双条件（`&&`）+ 计数器上限防死循环；参数 `lv`、`target` 自动推断为 i64
- `main`：调用宿主函数 → 元组标志位判断（`btn.0`）→ 元组取坐标（`btn.1`/`btn.2`）→ 字符串拼接上报

电量 22 时的完整输出（被测试验证过）：

```text
当前电量 22%（告急）
进入省电流程
已点击省电模式
共按下 3 次减键
```

## 10. 语言规则速查表

**语法速查**：

```text
func 名字(参数) -> 返回类型? { ... }      // 函数（-> 可省略）
let x = 表达式                            // 绑定
x = 表达式                                // 赋值（类型不变）
if 条件 { } else if 条件 { } else { }     // 分支（表达式形式必须带 else）
while 条件 { }                            // 循环
for i in 0..n { }                         // 区间循环（左闭右开）
break / continue                          // 循环控制
return 值?                                // 提前返回
(值1, 值2)                                // 元组；.0 .1 取值
```

**保留字**：`func let if else while for in return break continue true false`（12 个），加上 13 个内置函数名也不能用作函数名。

**内置函数**：abs / min / max / sqrt / floor / ceil / pow / len / contains / substr / to_i64 / to_f64 / to_str（详见 §7）。

**数字上限**：±9,223,372,036,854,775,807；溢出报错不回绕。

**嵌套上限**：64 层。**单次调用 / 元组**：8 个元素。

## 11. 这门语言刻意没有的东西（和替代方案）

| 没有 | 为什么 | 替代方案 |
|---|---|---|
| Map / 字典 | 破坏静态类型与性能 | 多个变量；元组；找宿主要函数 |
| 数组 | 同上 | 元组（固定几个）；宿主的集合函数 |
| 闭包 / 匿名函数 | 复杂度与安全 | 直接调宿主函数 |
| 异常 try/catch | 引入隐藏控制流 | 宿主返回 `(是否成功, 结果)` 元组；或让脚本终止 |
| 空值 null / None | 同上 | `(false, 占位值)` 标志位元组 |
| `import` 引入别的脚本 | 引擎保持极简 | 宿主会把公共库拼接进来（公共函数"凭空"可用，问宿主有哪些；注意别和 lib 撞名，撞了编译报错） |
| 字符串插值 `` `a${b}c` `` | 极简语法 | `"a" + to_str(b) + "c"` |
| 字符串方法（`s.trim()` 等） | 无方法调用 | 内置 4 个函数 + 宿主函数 |
| 并发 / 文件 / 网络 / 时间 / 随机数 | 安全边界 | 全部找宿主要函数（如果宿主提供了） |
| 分号 | 换行即结束 | —— |

**设计逻辑一句话**：脚本只做「计算 + 判断 + 调宿主函数」，一切有副作用的操作都过宿主的手——这让脚本跑不崩宿主、也跑不了不该跑的事。
